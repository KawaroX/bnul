# 2026-10-17 暂离时间解析问题

## 核实来源

2026-10-18 只读查询学校的 `user/lastMake`、`user/makeLife/<reservation>`、`user/breach/1/5` 及公开系统须知。未新建预约，未调用取消、结束或预约接口。原始响应保存在服务器私有诊断目录，不提交账号、姓名、凭据或预约 ID。

同一笔预约的字段：

| 字段 | 实际值 | 含义 |
|---|---|---|
| awayTime | 81578 | 当天零点起的秒数，即 22:39:38 |
| awayTimeM | 1359 | 当天零点起的分钟数，即 22:39 |
| awayRange | 22:39 | 官方页面的暂离时间显示值 |
| AWAY 变更记录 createdDate | 2026-10-17 22:39:38 | 门禁暂离事件，与秒数精确吻合 |
| 预约结束 | 23:00 | 原预约结束时间 |
| STOP 变更记录 createdDate | 2026-10-17 23:00:02 | 学校记录“预约完成使用” |

两笔历史暂离还分别返回 79475/1324/22:04 和 78955/1315/21:55，符合相同单位关系。脱敏字段保存在 `tests/fixtures/away_seconds.json`。

官网前端 `https://libseat.bnu.edu.cn/jsq-v/static/js/app.18c18001b15babcc9f3b.js` 将 awayRange 显示在暂离时间列；该文件 SHA-256 为 `a8ddf6d801dd6f071442e849bcdbe1daf239b52b2555bba4b98a76e6666eb1d2`。秒数含义由实际数据与同笔变更时间交叉确认，不是仅从字段名推测。

## 原因与影响

0.5.1 把 awayTime 交给只支持日期时间、时钟字符串、Unix 秒/毫秒时间戳的解析器，拒绝了五位数 81578。22:48 至 22:58 连续六轮报 DEADLINE_UNKNOWN，未执行取消、结束或重约。登录恢复已经成功，但告警无条件附加登录退避说明，造成误导。

按官网 30 分钟暂离规则，该次截止为 23:09:38；预约会先在 23:00 自然结束，所以应继续观察，无需释放重约。学校实际终态为 STOP，并记录正常完成。这一事件不证明真实自动重约成功。

## 修复与验证边界

0.5.2 解析当天秒数并交叉校验分钟和显示值；保留秒级精度与用餐豁免计算。自然结束更早时输出 actionRequired=false 与计算依据。字段缺失、超范围或相互冲突时不写预约，并留下最小诊断字段。

告警分类说明真实失败原因。夜间仍静默休眠，但 status 不再把尚未解决的业务故障显示为 healthy。

回放使用实际保存的字段、官方规则和事件时间，测试中将已经结束的历史记录还原为 AWAY；网络写操作使用内存替身。它验证计算和执行分支，不冒充对学校服务器完成了真实结束重约。

轮询监控能读状态、计算期限并在窗口内尝试操作。它不能保证网络和接口一直可用，也不能保证重约原位成功。按现有空闲 30 分钟的设置，其他入口新建的预约可能接近签到截止才被发现；若需要覆盖每笔新预约，应缩短空闲间隔或提供创建事件唤醒。
